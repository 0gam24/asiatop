# /목록, 오늘 빈틈 글감

운영자가 **"목록"**, `/목록`, "오늘 빈틈 키워드", "빈틈 목록", "글감 보여줘"라고 하면 실행한다.
운영자 지시(2026-10-07): "이런 식으로 오늘 빈틈 키워드를 찾아줘(awoo 목록 화면). Naver API 활용해서. 철저하게 데이터 중심으로."
계획 문서: `docs/28-naver-gap-200-plan-2026-10.md` (목표 하루 200달러).

## 순서

1. **최신화.** 봇이 커밋한 대기열을 받는다. 커밋 안 한 로컬 변경이 있으면 pull 을 건너뛰고 그 사실만 보고한다.
   ```bash
   git pull --ff-only origin main
   ```
   대기열 `docs/ops/pipeline-queue.json` 의 `updatedAt` 이 오늘(KST)이 아니면 그날 Actions 측정이 실패한 것이다.
   묻지 않고 로컬에서 다시 잰다(`.env.local` 의 HUB 키, 약 9분): `node scripts/audit/naver-pipeline.mjs --write`.
2. **다음 물결.** 오늘 결과가 있으면 API 를 부르지 않는다.
   ```bash
   node scripts/audit/next-wave.mjs --if-stale
   ```
   이 단계가 파일을 새로 썼으면(봇보다 먼저 잰 날) `docs/ops/next-wave.json` 을 main 에 바로 커밋·push 한다
   (`chore(ops): 다음 물결 측정 <날짜> [CF-Pages-Skip]`). 안 그러면 다음 날 봇 커밋과 겹쳐 pull 이 막힌다.
3. **띄우기.** `mcp__visualize__read_me`(modules `["interactive"]`)를 부른 뒤, 아래 출력을 그대로 `mcp__visualize__show_widget`(title `today_gap_picks`)에 넣는다.
   ```bash
   node scripts/audit/ops-widget.mjs --limit=10
   ```
4. **두 줄 요약.** 위젯 아래에 쉬운 말로 쓴다. 숫자는 위젯에 있는 측정값만 쓴다. 예상·전망은 쓰지 않는다.
   - 발행 현황: `node scripts/audit/ops-widget.mjs --count` 출력 그대로.
   - 다음 물결: 무엇이 뜨는 중·곧 뜸인지, 무엇이 꺾여 새 글 대신 갱신만 할지.
5. **끝.** 목록을 보여 주면서 먼저 글을 쓰지 않는다. 글은 운영자가 버튼을 누를 때만 쓴다.

버튼이 반응하지 않으면 운영자는 같은 문장을 채팅에 직접 쳐도 된다(예: `발행: 건보료 차량세금`).
버튼 문구는 슬래시로 시작하지 않는다. 슬래시로 시작한 버튼은 데스크톱 앱에서 메시지가 도착하지 않았다(2026-09-28 머니룩, 2026-09-25 awoo).

## 버튼 지시 처리

채팅에 들어온 문장의 첫 낱말로 가른다.

- **`발행: <검색어> …`** → 그 대기열 항목을 운영자 승인으로 본다(CLAUDE.md "목록 위젯의 [발행 지시]"). 확인 질문 없이 진행한다.
  1. `node scripts/audit/publish-cadence.mjs` 로 오늘 상한과 오늘 신규 수를 본다(루틴 PR 과 같은 하루 상한을 나눠 쓴다).
  2. 항목의 `condition`(1차 출처 확인 과제)을 먼저 푼다. 못 풀면 발행하지 않고 사유를 보고한다.
  3. `node scripts/audit/naver-ledger.mjs --check "<검색어>" <family>` 가 VETO 면 새 글 대신 기존 글 갱신을 제안한다.
  4. daily-post SKILL §3 흐름: content-strategist 브리프(맨 앞에 항목 `reasons`·`serp.top10`·`ledger.relatedSlugs`·`condition`) → content-agent →
     content-auditor PASS → 가드(claims·cadence·template·ai-style·safe) → `corepack pnpm exec astro build` → PR. frontmatter 에 `targetQuery: "<검색어>"`.
  5. 상한 안이면 publishedAt 오늘·브랜치 `content/daily-<오늘>` → CI green 뒤 `gh pr edit --add-label merge-approved <PR번호>` → 자동 머지 → URL 200 확인.
     상한이 찼으면 publishedAt 다음 날·브랜치 `content/daily-<다음날>` 로 라벨 없이 PR 을 올리고, 다음 날 00:07 KST 1회용 scheduled task
     (`mcp__scheduled-tasks__create_scheduled_task`, fireAt)로 라벨 부착·URL 200 확인을 맡긴다(2026-09-28 #465 선례).
  6. 보고는 daily-post §4 형식(발행 링크 블록이 맨 끝).
- **`보류: <검색어> …`** →
  ```bash
  node scripts/audit/queue-set.mjs --query "<검색어>" --status hold
  ```
  `docs/ops/pipeline-queue.json` 을 main 에 커밋·push(`chore(queue): 운영자 보류 <검색어> [CF-Pages-Skip]`) → 1~3단계로 목록을 다시 띄운다.
- **`눈확인: "<검색어>" = <첫 화면|한 번 스크롤|그 아래>`** → 운영자가 네이버 통합검색에서 웹문서 묶음 위치를 직접 보고 누른 값이다. Claude 가 네이버 화면을 대신 보지 않는다.
  ```bash
  node scripts/audit/queue-set.mjs --query "<검색어>" --eye "<값>"
  ```
  첫 화면 +10점·한 번 스크롤 +5점, 그 아래는 보류로 돌린다. 큐와 `docs/ops/radar/eye-offset.json` 을 커밋·push(`chore(queue): 눈 확인 <검색어> [CF-Pages-Skip]`) → 목록 다시 띄움. API 호출 없음.
- **`선점: "<주제>" …`** (다음 물결 칸, 우리 글 2개 이하) →
  ```bash
  node scripts/audit/wave-split.mjs --term "<주제>"
  ```
  세부 검색어(의도 꼬리 + 지식iN·블로그 제목에서 주제 뒤에 붙는 말)를 만들고, 검색량 0.5(실업급여 = 100) 이상만 실측해 자리가 열린 것을
  `빈틈:<검색어>` 항목(autoPick false)으로 넣는다. 넣은 것과 뺀 이유를 쉬운 말로 보고하고, 큐를 커밋·push(`chore(ops): 다음 물결 선점 <주제> 빈틈 N건 [CF-Pages-Skip]`) → 목록 다시 띄움.
  **선점은 글감을 목록에 올리는 것까지다.** 글은 운영자가 그 항목의 [발행 지시]를 눌러야 쓴다.
- **`갱신: "<주제 또는 검색어>" …`** → 그 주제 기존 글을 `updatedAt` 오래된 순으로 보여 준다(제목·URL·마지막 갱신일·`pnpm audit:rank` 순위가 있으면 순위).
  기존 글 URL 이 붙어 왔으면 그 글을 먼저 본다. 리프레시는 운영자가 고른 글만, daily-post 리프레시 규칙(본문 실질 변경 시에만 updatedAt·lastReviewed,
  제목·slug 불변, PR 당 리프레시 3편 이하)대로 한다.
- **`보류: "<주제>" 물결 …`** → `docs/ops/next-wave-seeds.json` 의 `ignore` 에 주제를 넣고(`seeds` 에 있으면 뺀다) 커밋·push → 목록 다시 띄움.

## 화면 읽는 법

- **글감 행**: 점수(70 이상 높음 · 45~69 중간)는 naver-pipeline.mjs 의 노출 가능성 점수다. 아래 줄은 그 점수를 만든 측정값이다.
  지식iN 같은 질문 수, 뺏을 수 있는 자리(웹문서 상위의 상업·오래된 문서), 위 5개 중 관공서·공단·도구 수, 최근 7일 기사 수, 검색량(실업급여 = 100), 우리 순위, 위 10개 구성.
- **"검색량 데이터랩에 안 잡힘"**: 데이터랩이 0 으로 준 검색어다. 0은 "검색 없음"이 아니라 이 눈금으로 안 잡힌다는 뜻이다(docs/28 1-2).
- **운영자 지정 글감**: 자동 선택이 꺼진 항목이다(민간 대출·질문과 검색량 적음·awoo 가 3위 안 등). 누르면 발행 지시로 들어간다.
- **기존 글 고칠 후보**: 오늘 측정에서 우리 글이 4~30위인 검색어다. 새 글보다 기존 글을 먼저 본다.
- **다음에 크게 뜰 주제** (`scripts/audit/next-wave.mjs`, 크기는 실업급여 최근 28일 평균 = 100):
  지금 뜨는 중 = 최근 7일이 직전 3주의 1.4배 이상·크기 8 이상 / 곧 뜸 = 감시 목록 묶음, 작년 이맘때 한두 달 뒤 1.5배 이상 / 커지는 중 = 1.2배 이상 /
  큰데 우리 글 적음 = 크기 30 이상·우리 글 2개 이하 / 꺾이는 중 = 0.6배 이하(새 글 대신 갱신만).
- **목표 줄**: `docs/revenue-log/private/` 최신 deep 파일의 최근 7일 평균이다. 위젯 출력에만 나가고 저장소에는 남지 않는다(약관 11조).

## 금지

- 새 브라우저 창을 열지 않는다. search.naver.com 을 자동으로 열거나 수집하지 않는다.
- 예상 수익·전망 문구를 쓰지 않는다. 애드센스 수치는 채팅 위젯·채팅 보고에만 쓴다.
- 대기열 밖에서 신규 글감을 고르지 않는다. 선점·눈 확인도 대기열을 거친다.
- 자매 사이트 awoo 주제(지자체 민생지원금·지역화폐·상품권 사용처·반값여행)는 목록에 올리지 않는다.
