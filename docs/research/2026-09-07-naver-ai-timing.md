## (2) 관찰한 검색결과 구조 5건 (PC 통합검색 HTML, curl, 2026-09-07 22:44 KST)

방법: `search.naver.com/search.naver?where=nexearch&query=...` 를 Chrome UA 로 curl. AI 브리핑 답변 본문과 "정보출처" 목록은 HTML 안에 JSON 으로 내장돼 있어 파싱 가능 (JS 렌더링 없이 확인). 블록 순서는 HTML 순서(`sc_new` 섹션). 원본: `research/serp/*.html`, 파서 `parse2.mjs`·`sources.mjs`.

### 2-1. "재산세 납부기간"
1. **AI 브리핑** (`data-aib-version="2"`): 첫 문장 즉답(굵게 "9월 16일(수)부터 9월 30일(수)") → `### 납부 대상 및 부과 기준` → `### 납부 방법 및 주의사항`, 불릿, 각 문단 끝 출처칩 `data-type="official"`. 정보출처 [1] 남양주시 blog.naver.com/nyjloving [2] 국세청 nts.go.kr [3] 네이버 인플루언서 in.naver.com. 하단 "실험 단계로 정확하지 않을 수 있어요".
2. **알기 쉬운 공공 정보**: 은평구·사상구·해운대·사하구·남양주시·청도군·연수구 공식 블로그 + 재테크 블로그 (전부 blog.naver.com).
3. 인플루언서(in.naver.com) → 4. 뉴스(뉴시스·뉴스클레임) → 5. **웹사이트: wetax.go.kr(지방세 월별 납부 안내), nts.go.kr(종부세 FAQ), seocho.go.kr** → 6. 인플루언서·블로그 개별 카드 → 7. 카페 4건 → 8. 지식iN 3건(세무사 답변) → 9. 블로그 6건("2026 재산세 2기분 납부기간 총정리", "9월에 또 내나요?") → 이미지 → 숏텐츠 생활경제.
- 독립 웹사이트 0건, asiatop 0건. 블로그 제목 패턴: 연도·월·"총정리"·"또 내는 이유".

### 2-2. "실업급여 조건"

### 3-4. 규칙 (수식)
기호: P = 관심도 피크일(전년 곡선 argmax 를 올해 제도 일정에 맞춰 이동), S = 상승 시작일(전년 곡선에서 ratio 가 피크의 30% 를 처음 넘는 날), L = 색인 지연(3~4일, 보수적으로 7일), R = 순위 안정화(7~14일).

```
신규 글  : D_pub  ≤ P − (L + R)  →  P − 14 ~ P − 10   (그리고 S − 7 이전)
리프레시 : D_ref  ≤ P − L        →  P − 7  ~ P − 4    (본문 실질 변경 시에만, lastmod 무변경 갱신 금지)
2봉 일정 : 개시일 P1, 마감일 P2 각각 적용. 마감 D-N 문구는 P2 − 7 이후 리프레시에서만 넣는다.
```
- P 는 달력 날짜가 아니라 **제도 앵커(신청 개시·고지서 발송·마감·개통)** 에 정렬한다. 앵커가 올해 미공지면 "미확인" 표기 후 전년 앵커 + 요일 보정.
- 트렌드 곡선이 P 이후 급락(근로장려금 9/2 67 → 9/6 11)하므로 P 를 넘긴 신규 발행은 남은 수요 30% 이하에 들어간다. 이 경우 신규 대신 다음 앵커(마감일) 리프레시로 돌린다.
- 검증: 발행 후 D+3 에 웹문서 API `site:` 검색으로 색인 확인, D+7 에 일반 질의 순위(naver-demand `ourRank`) 확인. 둘 다 0 이면 L·R 추정을 늘려 다음 시즌에 반영.

| 2. 수요·경쟁·공백 | 검색 API 4종 (`naver-demand.mjs`): `kinTotal`(지식iN 누적, 장기 수요), `blogPerDay`(최신 블로그 20건이 며칠에, 과열), `newsPerDay`(시의성), `official`(웹문서 상위 10 중 go.kr·or.kr 수), `ourRank`, `existing`(기존 글 겹침) | `gap=1`(기존 글 없음 + official ≥3) 이면 신규 후보, `existing` 히트면 리프레시. `blogPerDay` 40(하루 20건 이상)이면 블로그 과열 = AI 브리핑 UGC 경쟁 극심 → 공식 문서가 답 안 하는 하위 질문으로 좁힌다. `official` 이 10 이면 웹사이트 블록 진입 거의 불가 → AI 브리핑 인용만 노린다 | 오늘의 주제 1개 + 리프레시 1~3개 |
| 3. SERP 역설계 | `naver-serp.mjs`: 웹문서 top10(`title`·`description`, 정렬·날짜 없음), 블로그 top10(`title`·`description`·`bloggername`·`postdate`, `sort=date` 가능), 지식iN top5(`title`·`description`, `sort=sim/date/point`) | 2026-09-07 실측(30키워드): 웹문서 제목 평균 30.8자, 숫자 포함 42%, 연도 20%, 질문형 8%, 설명 107.7자, top3 의 61% 가 공식 도메인. 블로그 제목 30.9자, 숫자 45%, 연도 24%, 질문형 4%, 설명 119자. 결정 규칙: ① 제목 28~34자, 수치 1개 + 연도 1개 + 판단 1개("...하면 환수", "...이면 정기로") ② 질문형 제목은 상위에 드물다(4~8%) → 제목은 서술형, 질문은 H2 로 ③ description 첫 100자 안에 즉답 문장(AI 스니펫이 문장형으로 뽑는 단위) ④ 블로그 `postdate` 분포로 경쟁 글이 P 대비 며칠 전에 몰리는지 확인 → 그보다 L+R 만큼 앞선다 | 제목 3안, description 1안, 즉답 첫 문장 1안 |
| 4. 지식iN → H2·FAQ | 지식iN API `sort=date` 로 최근 질문 30~50건 + `sort=point` 상위 10건의 `title`·`description` | 같은 의도끼리 묶어 빈도순. 공식 문서(단계 2 의 official 문서 본문)가 직접 답하지 않는 질문 = 정보 공백(예: 관찰 지식iN "정기·반기 둘 다 안 됨", "4월 일용근로가 3.3% 로 신고돼 반기 불가", "재산세 7월·9월 두 번 나오나요"). H2 는 그 질문을 그대로 30~50% 질문형으로, 바로 아래 2~3문장 즉답(BLUF). FAQ 3~5개는 남은 롱테일 질문, 답 40~60단어. 수치·기한은 go.kr 원문 확인 후 단정, 아니면 "약"·"미확인" | H2 목록(질문형 30~50%), FAQ 3~5, 각 답 첫 문장 |
| 5. 발행 후 측정·학습 | D+3: 웹문서 API `site:asiatop.co.kr <제목>`; D+7·D+14: `naver-demand` `ourRank`; 주 1회: 목표 질의 SERP HTML curl → "정보출처" 파싱(가능, 2절 확인) → 인용 여부 | 색인 0 이면 L 상향, 순위 0 이면 R 상향, 인용 0 이면 즉답 문장·출처 링크·질문형 H2 점검. 기존 제목은 건드리지 않음(P4 트랙 예외만) | `docs/revenue-log/naver-*.json` 에 P·L·R·인용 기록, 다음 시즌 캘린더에 반영 |

주의: 웹문서 API 결과는 통합검색 첫 화면과 다르다(2-6). 최종 판단은 반드시 SERP HTML 관찰과 함께 한다.

## (5) 지역·연령 세그먼트 활용

### 5-1. 규칙
- 연령 코드는 3-1 표. 지역 필터는 트렌드 API 에 없음(지역은 검색어 자체에 넣는다: "서울 청년 이사비", "부산 추석 지원금"). 미확인: 데이터랩 웹 UI 의 지역 옵션 API 제공 여부.
- `ratio` 는 호출 내 상댓값이므로 **세그먼트 간 절대 비교 불가**. 쓸 수 있는 것은 (a) 같은 호출 안에서 키워드끼리의 순위·비율, (b) 세그먼트별 **곡선 모양(피크 시점·반감기)** 두 가지다.
- 절차: 같은 키워드 그룹 3~5개를 ① 필터 없음 ② `ages` 세그먼트 ③ `device` 로 각각 호출 → 세그먼트에서만 커지는 키워드 = 그 세대의 주제, 피크가 앞당겨지는 세그먼트 = 그 세대용 글을 먼저 낸다.
- HUB 호출 메모: `ages: ["3","4","5"]` 단독 1회 500 오류, 같은 요청에 `device: "mo"` 병기 또는 `ages: ["3"]` 단독은 정상(원인 미확인, 재시도 로직 필요).

### 5-2. 실측 (2026-01~08 월간, 같은 호출 안 "연말정산" 1월 = 100 기준)
| 세그먼트 | 청년도약계좌 | 기초연금 | 해석 |
|---|---|---|---|
| 필터 없음 | 1월 10, 5월 12, 6월 12, 8월 3 | 5, 3, 2, 3 | 두 주제 모두 연말정산 대비 소규모 |
| 19~24세 | **1월 71, 5월 83, 6월 67, 8월 20** | 1 | 청년 계좌는 20대 초반 관심이 전체의 7배 규모, 5~6월(청년미래적금 갈아타기) 2차 피크 |
| 19~34세 + 모바일 | 65, 73, 74, 21 | 1~3 | 모바일 집중 |
| 여성 | 19, 22, 21, 6 | 6, 3 | 기초연금은 여성 비중 상대적 우위 |
| PC | 3, 3, 4, 1 | 1 | 청년 금융 주제는 PC 검색이 거의 없음 → 모바일 첫 화면(AI 브리핑·즉답)이 사실상 전부 |
| 60세 이상 (2025년, 연말정산 1월 = 100) | 19, 13, 8, 7 (하락) | **1월 43, 2월 26, 이후 20~27 유지, 12월 27** | 60+ 는 기초연금이 연중 안정 수요, 1월(인상 고시) 피크 |

### 5-3. 주제 선정 적용
- 20대(코드 3~4): 청년도약계좌·청년미래적금·국가장학금·청년 이사비. 모바일 100% 가정 → 첫 화면 즉답 1문장 + 표 1개, 긴 서론 금지. 피크가 제도 발표 직후 급등·급락하므로 신규는 발표 D+1 이 아니라 **다음 앵커(2차 신청·마감) P−14** 에 맞춘다.
- 60대(코드 11): 기초연금·노인일자리·건강검진·본인부담상한제. 연중 완만, 1월 인상 고시가 피크 → 12월 중순 리프레시. 여성 비중 높음 → 배우자·유족 관점 FAQ.
- 40~50대(7~10): 재산세·종부세·연말정산·자녀 국가장학금. 마감형 2봉 → 리프레시 2회.
- 세그먼트 곡선은 참고 신호이고, 최종 주제는 `/topics`(GSC + naver-demand) 규칙을 따른다.
