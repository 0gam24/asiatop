### 1-2. 검색량

- 오늘 대기열의 proposed 25건 중 데이터랩 30일 검색량(실업급여 = 100 눈금)이 0보다 큰 항목은 6건이다. 나머지 19건은 데이터랩이 0으로 준다.

## 2. 측정에서 바로 나오는 결론

1. 색인은 막히지 않았다. 노린 검색어의 순위가 막혀 있다.
2. 지금 빈틈 점수(자리 열림·빈자리·관공서 없음·지식iN 같은 질문 수)로 고른 12편 가운데 9~20일 안에 10위 안에 든 글은 없다. 이 점수를 그대로 둔 채 편수만 늘릴 근거가 없다.
3. 빈틈 검색어 대부분은 실제 검색 수를 모른다. 1위를 해도 몇 명이 오는지 모른다.
4. 머니룩 주제별 1000회당 수익을 모른다.
5. 단계 올리기 조건(직전 14일 신규 글 중 30위 안 30% 이상, 10위 안 1편 이상)은 지금 값으로 충족되지 않는다.

그래서 첫 일은 편수를 늘리는 것이 아니라 **무엇이 실제로 순위와 클릭과 수익을 내는지 재는 것**이다.

### 3-3. 고르는 규칙 고치기 (자료가 쌓인 뒤, 측정 근거로만)

- **월간 검색 수 하한**: 검색광고 API 값과 서치어드바이저 클릭을 맞대어 정한다. 정하기 전에는 하한을 쓰지 않는다.
- **순위에 든 글의 공통점**: 지금 10위 안 4개는 모두 숫자가 든 검색어다. 표본이 4개라 아직 규칙으로 쓰지 않는다.
- **웹문서 결과 수 (2026-10-07 적용, 점수 v0.2)**: 1-5 표본(691편)에서 결과 수가 적을수록 10위 안 비율이 높았다. 대기열 점수에
  3만 건 미만 +5, 10만~100만 −10, 100만 이상 −15 를 넣었다(3만~10만 0, 값이 없으면 0). 검색량 눈금(데이터랩)은 지식iN·실유입과 함께
  수요 점수(큰 쪽 한 번)에 넣었다. 지식iN 질문 말투 조각은 후보에서 뺀다.
- **검색 신호 감점 (2026-10-07 적용)**: 같은 날 드라이런에서 "최저임금 만오백원이"(지식iN 7 · 블로그 제목 0 · 눈금 0 · 웹문서 17건)가
  결과 수 가점으로 85점 1위가 됐다. 후보 낱말은 지식iN 제목에서 뽑으므로 지식iN 같은 질문 수는 독립된 신호가 아니다.
  그래서 데이터랩 눈금 > 0 · 블로그 제목 3회 이상 · 실유입 중 하나도 없으면 −10, 결과 수 3만 미만 가점도 주지 않는다.
  하한(발행 금지)이 아니라 정렬 감점이다. 다만 대기열에 올리는 문턱(45점)·자동 선택 문턱(55점)은 그대로라, 감점으로 문턱 아래가 되면 올라가지 않는다.
- **자동 선택의 수요 조건 (2026-10-07 적용)**: 감점을 넣은 두 번째 드라이런에서도 "주휴수당 매커니즘"·"건보료 차량세금"(블로그 제목 0 · 눈금 0)이
  자동 선택 1·2위였다. 자동 선택(`autoPickOf`)의 수요 조건에서 지식iN 같은 질문 수를 빼고 검색 신호(눈금 > 0 · 블로그 제목 3회 · 실유입)만 본다.
  신호가 없는 항목은 대기열에 남고 `condition` 에 "검색 신호 없음 — 운영자 지정 필요"가 붙는다. 운영자 [발행 지시]로는 그대로 쓸 수 있다.
  자동 선택 항목이 없으면 그날 신규는 0편이다(이전과 같은 규칙).
- **검색량 먼저 (2026-10-08 적용, 1-6 근거)**: 루틴은 자동 선택 항목 중 검색량(`demand.rel30`) 0.5 이상을 먼저 점수 순으로 쓴다(`.claude/skills/topics/SKILL.md` §2-3, 루틴 프롬프트 2-1).
  선점 항목(`wave-split`)도 파이프라인과 같은 `autoPickOf` 로 자동 선택 여부를 정한다(그 전에는 운영자 [발행 지시]로만 썼다).
- 이 규칙들의 결과는 다음 표본(매주 월요일)과 결과표(`gap-outcomes.md`)로 본다.
- **주제 수익 배수**: 3-1 #4 자료로 머니룩 주제 묶음별 상대 배수를 만든다. 공개 저장소에는 금액 없이 배수만 둔다.
- 바꾼 규칙은 5절에 날짜·근거와 함께 남긴다.

### 3-4. 매일 운영

- **목록** (`.claude/commands/목록.md`): 오늘 측정분 빈틈 글감, 다음에 크게 뜰 주제, [발행 지시]·[보류]·[눈 확인]·[선점] 버튼. 운영자가 "목록"이라고 하면 띄운다.
- **신규**: KST 09:05 루틴과 운영자 [발행 지시]가 같은 하루 상한(A단계 2편)을 나눠 쓴다.
- **리프레시**: `naver-striking.md` 의 "4~30위 중 검색량이 잡히는 글"부터 갱신한다(1-6). 그다음 검색량이 오른 주제의 기존 글(2026-09-07 실측: 급등 키워드 대부분이 이미 기존 글이 있는데 10위 밖이었다, docs/26).
- **매일 자동 선점 (2026-10-08)**: 새벽 대기열 측정 뒤 `wave-auto.mjs` 가 뜨는 주제(`next-wave.json`)와 감시 목록·큰 키워드를 돌아가며 하루 6개 쪼갠다. 검색량 0.5 이상이면서 자리가 열린 세부 검색어만 대기열에 더한다. 같은 주제는 7일 안에 다시 쪼개지 않는다(`docs/ops/radar/wave-auto-log.json`). 승인·제안 항목 재측정 예산은 30 → 60.
