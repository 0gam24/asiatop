# inbox, 네이버 콘솔 내보내기 투입함

네이버 서치어드바이저와 네이버 애널리틱스는 **공개 API 가 없다**(2026-09-08 확인, 네이버 오픈 API 목록에
데이터랩·검색 API 만 존재). 그래서 노출·클릭 실측은 사람이 콘솔에서 내려받아 여기에 넣어야 한다.

## 넣는 방법 (주 1회 권장, 적어도 월 1회)

### 1. 서치어드바이저 (필수)

searchadvisor.naver.com → 리포트 → 검색 노출/클릭 현황 에서 **탭 2개 × 기간 2개 = 파일 4개**를 받는다.

| 탭 | 기간 | 왜 |
|---|---|---|
| **검색어** 탭 | 최근 90일 (최대치) | 롱테일 검색어까지 넓게 본다. 개선 후보 3분류의 기준 |
| **검색어** 탭 | 최근 7일 | 요즘 무엇으로 들어오는지. 파이프라인의 최근 유입(inbound7d) 재료 |
| **문서** 탭 | 최근 90일 | 어느 글(URL)이 노출·클릭을 받는지 |
| **문서** 탭 | 최근 7일 | 최근 리프레시·신규 글이 붙기 시작했는지 |

- 기간은 콘솔 달력에서 고른 뒤 CSV 다운로드.
- **파일 이름에 기간을 넣는다.** 콘솔이 붙여 주지 않으면 이름 끝에 직접 붙인다.
  예: `검색어_20260702~20260929.csv`, `문서_2026-09-23_2026-09-29.csv`.
  기간을 못 읽으면 경고가 뜨고, 그 파일은 다른 파일과 섞지 않는다.
- 같은 탭·같은 기간 파일을 두 번 넣으면 두 번째는 건너뛴다(값을 두 번 세지 않는다).

### 2. 요약 화면 총 클릭 수는 손으로 적는다 (필수)

내보내기 파일에는 상위 행만 들어 있어 합계가 사이트 전체보다 작다. 같은 화면 위쪽 **요약 숫자(총 클릭, 총 노출)**를
90일·7일 각각 이 폴더의 `manual-totals.txt` 에 적는다. 한 줄에 하나, 형식은 자유롭게 이 정도면 된다.

```text
# 서치어드바이저 요약 화면 (2026-09-30 확인)
90일 클릭 1234
90일 노출 56789
7일 클릭 120
7일 노출 5600
```

스크립트가 이 값으로 "내보내기가 전체 클릭의 몇 %를 담았는지"(exportShare)를 계산한다.

### 3. 네이버 애널리틱스 (선택)

analytics.naver.com → 유입분석 → 검색어 → CSV 다운로드. 파일 이름에 기간을 붙이는 방법은 같다.
애널리틱스 값(유입수)은 서치어드바이저 값(클릭)과 **더하지 않고** 따로 기록한다. 교차 확인용이다.

### 4. 실행

받은 파일을 이 폴더에 그대로 넣고:

```bash
pnpm audit:console
```

한글이 깨진 CSV(엑셀 호환 EUC-KR)도 자동으로 읽는다. 엑셀 파일(.xlsx)은 못 읽으니 CSV 로 받는다.

## 멈추는 경우

필수 컬럼을 하나라도 못 찾은 파일이 있으면 **JSON 을 쓰지 않고 종료 코드 1** 로 멈춘다.
읽은 헤더를 그대로 보여 주니, 콘솔 버전이 바뀌어 이름이 달라졌으면 알려 주면 후보 목록에 추가한다.

| 파일 | 필수 컬럼 (이름 변형 자동 인식) |
|---|---|
| 서치어드바이저 검색어 탭 | 검색어, 클릭, 노출 |
| 서치어드바이저 문서 탭 | 검색 웹문서(또는 URL), 클릭, 노출 |
| 네이버 애널리틱스 검색어 | 검색어(유입검색어), 유입수 |

CTR(%)·순위 컬럼은 있으면 쓰고 없어도 된다. 제목 줄이 헤더 위에 붙어 있어도 된다.

## 결과

| 파일 | 담기는 것 | 커밋 |
|---|---|---|
| `docs/revenue-log/naver-console-YYYY-MM-DD.json` | 묶음(출처·탭·기간)별 합계, 분류별 건수, 상위 문서 URL 20개, 요약 화면 총계 대비 비율 | 커밋 |
| `docs/revenue-log/private/naver-console-YYYY-MM-DD.json` | 검색어 원문 행, 분류별 검색어 목록 | gitignore, 커밋 안 됨 |

콘솔에는 가장 긴 기간의 서치어드바이저 검색어 묶음으로 개선 후보 3분류가 뜬다.

| 분류 | 뜻 | 다음 단계 |
|---|---|---|
| ① 노출은 되는데 클릭이 안 붙는다 | 검색 결과에 보이지만 안 눌린다. 제목·설명 문제 | docs/24 P4 트랙(제목·메타 전용 도구), 운영자 승인 필요 |
| ② 클릭은 나는데 우리 순위가 낮다 | 더 올릴 여지가 있다 | /topics 리프레시 후보 |
| ③ 수요는 있는데 우리 글이 없다 | 빈자리 | 1차 출처 확인 후 신규 후보 |

`글` 칸에 "매칭 불확실" 이 붙으면 검색어와 글을 기계가 확신하지 못한 것이니 사람이 확인한다.

문서 탭 묶음은 URL 을 우리 글(article)·클러스터 허브(hub)·홈(home)·프루닝된 주소(pruned)·그 밖(other)으로 나눠 센다.
프루닝된 주소에 아직 노출이 잡히면 301 이 네이버에 반영되는 중이라는 뜻이다.

## 이 폴더의 원본 파일은 커밋되지 않는다

`.gitignore` 에서 이 폴더를 제외했다(README 만 추적). `manual-totals.txt` 도 여기 두니 커밋되지 않는다.
원본과 검색어 원문에는 우리 사이트로 들어온 검색어가 그대로 들어 있어, 공개 리포지토리에는 합계·건수만 남긴다.
